# Building The Last IceyPop for the Aurora launcher

This wraps the static-HTML game in a Tauri 2 desktop shell and assembles the
drop-in folder that the Aurora launcher copies into
`%LOCALAPPDATA%\Aurora\Games\the-last-icey\`.

## Repo layout

```
the-last-icey/
├── web/                  game source (index.html + js + css + assets)
├── src-tauri/            Tauri 2 wrapper
│   ├── Cargo.toml
│   ├── tauri.conf.json
│   ├── src/main.rs
│   ├── capabilities/
│   └── icons/            generated by `cargo tauri icon` (gitignored)
├── docs/wireframes/      design assets — not shipped in the build
├── launcher.json         Aurora launcher metadata (copied into drop folder)
├── dist-readme.md        README shipped next to the exe (renamed to README.md on copy)
├── build.ps1             one-shot build script
└── readme.md             game-level README
```

## Prereqs (Windows dev box)

1. **Rust toolchain** with the MSVC target: <https://rustup.rs>
2. **Tauri CLI 2.x**:
   ```powershell
   cargo install tauri-cli --version "^2"
   ```
3. **Visual Studio Build Tools** (Desktop development with C++) — Rust needs this for the MSVC linker.

WebView2 SDK and runtime headers are pulled in by Tauri at build time.

## Build

```powershell
pwsh ./build.ps1
```

The script:
1. Runs `cargo tauri icon web/assets/images/icee-icee2.png` once (if icons missing) to populate `src-tauri/icons/`.
2. Runs `cargo tauri build --no-bundle` to produce a raw exe at `src-tauri/target/release/the-last-icey.exe`.
3. Assembles `dist/the-last-icey/` with:
   - `the-last-icey.exe`
   - `launcher.json`
   - `README.md` (copy of `dist-readme.md`)

That folder is what you hand to Aurora.

## Manual build (if you want to skip the script)

```powershell
cd src-tauri
cargo tauri icon ../web/assets/images/icee-icee2.png    # first run only
cargo tauri build --no-bundle
cd ..

# Assemble drop folder yourself:
mkdir dist\the-last-icey
copy src-tauri\target\release\the-last-icey.exe dist\the-last-icey\
copy launcher.json                                 dist\the-last-icey\
copy dist-readme.md                                dist\the-last-icey\README.md
```

## Tweaking

- **Window title / size**: `src-tauri/tauri.conf.json` → `app.windows[0]`.
- **Bundle identifier**: `src-tauri/tauri.conf.json` → `identifier` (currently `com.tflinch.thelasticey`). Changing this orphans existing save data — see the dist README for the WebView2 storage path.
- **App version**: bump in three places — `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json`, and `launcher.json`. Keep them in sync.
- **Cover gradient**: `launcher.json` → `cover`.

## What was changed for the wrapper (vs the browser version)

- Runtime files moved from repo root into `web/`. All relative paths inside `index.html` survived the move untouched.
- `web/css/styles.css` no longer @imports Poppins from Google Fonts (no-network constraint). Falls back to `Segoe UI` / `system-ui`. The commented `@font-face` stub at the top of the file documents how to restore Poppins with vendored woff2 files.
- `assets/wireframes/` moved to `docs/wireframes/` so 1.8 MB of design PNGs don't get bundled into the exe.

That's it — the game logic itself is unchanged from `tommy`.

## Smoke test status

I could not produce the built `.exe` in this environment — no Rust toolchain in the WSL sandbox. The scaffolding is complete and should build cleanly on a Windows box with the prereqs above. Likely first-build pitfalls:

- **Icon generation failure** if `web/assets/images/icee-icee2.png` is too small to downscale — it's currently 200×200, which is the minimum Tauri accepts. If it complains, swap in any 512×512 or larger PNG.
- **MSVC linker missing** if VS Build Tools haven't been installed. The error is loud and self-explanatory.
- **WebView2 missing on Win10 < 22H2** at runtime — the dist README covers this.

If anything else breaks, the exact reproduction is `cd src-tauri && cargo tauri build --no-bundle --verbose` to see the full error.
